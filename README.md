# 剪报连载接续工作台

面向地方史整理与报刊收藏者的剪报连载接续工具：针对刊头被裁、
「下转某版」线索断开的老报纸剪报，帮助把散页重新排成正确的阅读顺序。

全部数据保存在本机（`./scans` 图片 + `./clippings.db` SQLite 数据库），
不依赖任何外部服务，刷新或重启后进度自动恢复。

## 运行环境

- Python 3.12（3.10+ 亦可）
- 依赖见 `requirements.txt`（仅 Flask）

## 安装与启动

```bash
pip install -r requirements.txt
python app.py
```

启动后在浏览器打开 <http://127.0.0.1:5000> 。

## 使用流程

1. **导入扫描图**：顶栏「导入扫描图」，可多选（png/jpg/gif/webp/bmp）。
2. **登记线索**：点击左侧缩略图，在中间阅读区放大查看（滚轮缩放、拖动平移），
   逐页填写可见日期范围、版次、正刊/副刊、栏目名、段首/段尾短句、
   「上接/下转」指向，然后「保存线索」。
3. **框选原文证据**：段首/段尾短句、「上接/下转」四个字段保存线索后，点字段旁
   「框选原文」，在阅读区（可先缩放、平移）拖出矩形即保存。坐标按**原图比例**
   （0~1）存储，与缩放/平移无关；重画只替换该字段的旧框，其他字段不受影响。
   保存后字段旁出现「查看原文」，刷新页面或点击矛盾卡片中的同名入口，都会打开
   对应扫描页并**居中高亮**该证据框（地址栏 `#p=<页>&f=<字段>` 深链）。
4. **拖排顺序**：把页面「＋排序」放入排序区，拖动卡片调整先后；
   两页之间的箭头显示接续强度（绿＝有线索，灰虚线＝无线索，橙＝待复核）。
5. **分析接续**：点击「分析接续」，系统给出：
   - **候选顺序**：多个方案并列，每个方案附逐步依据，可一键采用
     （已锁定页面保持不动）；
   - **矛盾与疑点**：如短句指向与日期先后冲突，定位到具体页面和线索字段，
     已框选原文的字段可直接「查看原文」；
   - **缺页与最小缺口范围**：「下转」悬空、日期间隔等，标出至少缺几页/期。
6. **确认与纠错**：确认无误的页面点 🔒 锁定；排错了点「撤销」逐步回退。
7. **修改线索**：某页线索改动后，只有它与相邻两页的接续被标记「待复核」
   （橙色「!」），其余排序不受影响；复核后点击「!」或「复核全部过期」清除。
8. **导出**：顶栏「导出 JSON 索引」，得到含阅读顺序、来源文件、
   接续依据、缺口、矛盾与**原文证据框坐标**的 JSON 文件。

## 接续规则（重要）

- 强证据：段尾/段首短句重叠、「上接/下转第X版」指向（限同刊期或相邻刊期）；
- 硬约束：日期先后——强证据与日期冲突时列为矛盾并定位线索；
- 疑点：正刊/副刊归属不一致；
- **同版次（版次重用）与同栏目名只作弱参考，绝不单独作为相邻依据**——
  每天都有「第3版」，同版号不代表相连。

## 导出 JSON 格式

```json
{
  "generated_at": "导出时间",
  "reading_order": [{"seq": 1, "page_id": 1, "source_file": "原始文件名",
                     "stored_file": "scans/存储名", "date_start": "...", "edition": "...",
                     "section": "...", "column_name": "...", "locked": true, "stale": false,
                     "evidence": {"last_phrase": {"x": 0.1, "y": 0.2,
                                                  "w": 0.3, "h": 0.4}}}],
  "unplaced": [{"page_id": 4, "source_file": "..."}],
  "links": [{"from": 1, "to": 2, "score": 19, "reasons": ["..."], "warnings": []}],
  "gaps": [{"after": 2, "before": 3, "min_missing": 1, "severity": "high",
            "message": "...", "basis": "..."}],
  "contradictions": [{"type": "date_conflict", "severity": "error",
                      "pages": [5, 1], "clues": ["last_phrase", "first_phrase"],
                      "message": "...", "evidence": ["..."]}],
  "rules_note": "规则说明"
}
```

证据框 `x/y/w/h` 均为相对原图宽高的比例（0~1），仅在该页存在证据框时出现；
`/api/state` 中页面对象的 `evidence` 字段与导出 JSON 使用完全相同的结构。

## 测试

```bash
python test_solver.py   # 求解器单元测试（成链规则、多解、矛盾、缺口、锁定）
python test_app.py      # 接口冒烟测试（使用临时目录，不影响真实数据；含证据框
                        # 保存/读取/导出、失败不写入、旧库自动迁移）
node test_geometry.js   # 证据框坐标换算（缩放/平移往返、越界与非正宽高拒绝）
```

## 文件结构

```
app.py            Flask 后端（页面、证据框、排序、锁定、撤销、复核、分析、导出）
solver.py         约束求解器（纯标准库，可独立测试）
templates/        单页界面
static/           前端样式与逻辑（SVG 缩放阅读区、证据框拖选、拖拽排序）
  geometry.js     证据框坐标换算纯函数（浏览器/Node 共用）
scans/            导入的扫描图（自动创建）
clippings.db      SQLite 数据库（自动创建；旧库启动时自动补齐 evidence 表）
```
